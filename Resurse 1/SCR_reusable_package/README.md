# SCR Reusable Website Assets Package

This package contains reusable media, document assets, extracted text content, and source indexes from the old Scoala Romaneasca Eindhoven website clone.

It is intended for media and content extraction during the website rebuild. It is not a production code export.

## Contents

- `manifest.json` - machine-readable registry of every copied reusable asset, with stable IDs, categories, original paths, suggested uses, and alt text.
- `content-extract.json` - extracted titles, headings, text blocks, image references, and reusable page content from the old HTML pages.
- `placement-suggestions.json` - recommended places to use assets/content in the new website.
- `assets/` - deduplicated reusable media and documents, grouped into clear categories.
- `source-reference/page-index.json` - index of the original top-level clone pages and their likely usefulness.
- `source-reference/original-file-map.json` - map from original clone files to copied package files.

## Recommended Destination

Copy this entire folder into the new website as:

`public/reusable/`

After copying this folder into the new website, ask Codex to read public/reusable/manifest.json and public/reusable/placement-suggestions.json before placing assets into components.

## How Codex Should Use This Package

Codex should treat `manifest.json` as the source of truth for reusable media. Components should reference assets by their `id` first, then resolve the actual file path from the manifest.

Example workflow:

1. Read `public/reusable/manifest.json`.
2. Select assets by `id`, `category`, or `suggestedUse`.
3. Use the asset `path` in components, typically under `/reusable/assets/...` when served from `public/reusable/`.
4. Use the included `alt` field as the starting point for accessible image text.
5. Read `public/reusable/content-extract.json` for reusable copy, headings, and page context.
6. Read `public/reusable/placement-suggestions.json` before deciding where assets belong.

## Important Limits

The original generated HTML/CSS/JS should not be reused directly as production code. The old clone was generated by a website builder and contains bundled scripts, duplicated styles, tracking/embed code, and external-service artifacts.

This package is for media/content extraction only. Rebuild components cleanly in the new website and pull only approved assets and copy from this package.
